# Ответы бизнеса

Карточка, которую ведущий выдаёт в чат на этапе clarify.

> Email сравниваем без учёта регистра, пробелы по краям обрезаем. Позиция в очереди считается отдельно для каждого типа оборудования, с 1, в порядке подачи. Активная заявка — зарезервированная или в очереди; повторная подача той же заявки ничего не меняет, причину не перезаписываем. Одновременная подача заявок на последнюю свободную единицу — вне scope лабы, защиту от гонок не делаем. Остальное — на ваше усмотрение, но запишите решение в спеку.

## Что решено в этом чекпоинте

Чекпоинт собран из прогона ведущего 27.10. На три вопроса `/speckit.specify` там ответили «рекомендованными вариантами»:

| Вопрос агента | Ответ | Следствие |
|---|---|---|
| Q1. Коды HTTP и формат ошибок | A: 200 для успеха, 400 для всех отказов, тело `{error, message}` | FR-010 |
| Q2. Повторная заявка с другой причиной | A: игнорировать новую причину, вернуть существующую заявку | FR-005, US3 |
| Q3. Атомарность резервирования последней единицы | A: гарантировать, с конкурентным тестом | SC-005, задача T022 |

Ответ на Q3 расходится с карточкой (там конкурентность вне scope). Это живой пример «додумывания»: рекомендованный вариант агента добавил требование, которого нет в брифе, и implement потратил на него около 18 минут.
